## 1. Defect Description
Inverted color channel evaluation in `classify_mask_region()`. When image arrays were ingested via standard OpenCV BGR channel representation without explicit color conversion, the Blue and Red channels inverted. Unmasked subjects with warm natural skin tones were evaluated as having high Blue channel dominance over Red, causing the algorithm to falsely classify bare human faces as wearing a "Surgical Blue Mask".

## 2. Steps to Reproduce
1. Ingest an unmasked face image via standard OpenCV BGR channel ordering.
2. Call `classify_mask_region(face_roi)`.
3. Check condition in `src/detector.py`:
   ```python
   is_surgical_blue = (b_mean > r_mean + 15) and (b_mean > 85)
   ```
4. Observe that warm skin pigment ($R \approx 190, B \approx 120$) is read with channels inverted ($B=190, R=120$), evaluating `190 > 120 + 15` as `True`.
5. The algorithm outputs `label = "Mask"` with confidence `0.95` on an unmasked face.

## 3. Expected vs. Actual Behavior
- **Expected:** An unmasked bare human face must be classified as `No Mask` regardless of source ingestion format.
- **Actual:** Bare faces with warm skin tones were falsely classified as wearing a surgical blue mask (`Mask`).

## 4. Root Cause Analysis
OpenCV default file reader (`cv2.imread`) loads image buffers in BGR format, whereas Streamlit and PIL use RGB format. `classify_mask_region()` assumed incoming pixel data was strictly RGB, but lacked defensive channel ordering validation. When BGR was passed directly, channel index 0 (Blue) and channel index 2 (Red) swapped, corrupting the color classification logic.

## 5. Developer Resolution (Applied by Software Developer Agent)
- In `src/utils.py`: Enforced strict RGB colorspace normalization inside `load_and_validate_image()` via `cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)`.
- In `tests/test_utils.py`: Added automated test `test_bgr_to_rgb_and_back` to guarantee deterministic colorspace roundtrips.
- In `src/detector.py`: Added defensive channel order assertions and bounds verification in `classify_mask_region()`.
